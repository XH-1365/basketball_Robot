01这是什么

一台 RoboMaster 步兵机器人的底盘控制固件。跑在 C 型开发板上，管五件事：

四个全向轮

通过 CAN 总线控制 4 个 M3508 电机，做全向平移 + 旋转。 摇杆输入 → 逆运动学解算 → 四轮目标转速 → PID → 电流指令。

一路步进（俯仰）

TB6600 驱动器 + 两相步进，硬件 PWM 发脉冲。 方向键控制升降，下端有限位开关做零位保护。

三路无刷（DShot）

BLHeli_S 电调，TIM8 三通道 + DMA 发 DShot300 数字油门。 A 键使能，LB/RB 调档。

两路输入源

蓝牙遥控（塔克模块）和 K210 视觉跟随，二选一， 用 B 键切换模式。

两种运行模式

模式数据来源底盘行为
RC 遥控 USART1 · 蓝牙模块的摇杆值 摇杆直接映射 vx / vy / w，人在环，想怎么走怎么走
FOLLOW 跟随 USART6 · K210 报的目标偏角 只做朝向跟踪：原地转向对准人，不前进不后退

跟随模式的距离保持功能已关闭（K210_FOLLOW_VX_ENABLE = 0）， 改这一个宏就能恢复「追人」。

怎么切换模式

按蓝牙手柄的 B 键（key2 的 bit1）。按下瞬间切换一次，不是按住。 切换时会清四轮 PID 积分，防止残留导致窜车。

02硬件拓扑

先看整体，后面再逐个讲线。所有外设都挂在 C 板上，C 板是唯一的「大脑」。

一眼要记住的一件事

右上角那条蓝色虚线——USART6 被 K210 和调试打印同时占用。 这是整套硬件里唯一「一线两用」的地方，也是最容易出怪问题的地方，第 3.3 节详细说。

03接线映射（核心）

这一节是全文最该背下来的部分。左边是「板上引脚的物理名字」，右边是「它接去哪」， 中间是「代码里谁在用」。

3.1 电源与共地

先接共地，再接信号

所有外设（蓝牙模块、K210、USB-TTL、步进驱动器、电调）必须与 C 板共地。 不共地时信号电平没有参考，表现是「有时候能收有时收不到」「一碰线就乱跳」—— 这类问题查代码永远查不出来。

项目取值说明
C 板供电底盘 24V（RM 标准）经分电板进 C 板，板上有 DC-DC 出 5V / 3.3V
逻辑电平3.3V所有串口、DShot、步进信号都是 3.3V，不要接 5V 信号
步进驱动器独立 12~24VTB6600 的 VCC/GND 单独供电，只共地不共用电源
电调电池直供BLHeli_S 动力电从分电板取，信号线只走 DShot，不要给电调灌 5V BEC 反送

两路 CAN，都是 1 Mbps（Prescaler=3, BS1=9TQ, BS2=4TQ，APB1 42 MHz ÷ 42 = 1 MHz）。

为什么「不要改公式」

逆解算的是几何关系（四个轮轴指车体对角线，轮速 = 速度场在该方向的投影）。 某个轮子转反只有两种可能：电机装反了、或者 DIR 宏写错了。 改公式会把本来对的三个轮子一起搞乱。

3.3 串口（两路，都 115200 8N1）

外设引脚参数接什么
USART1PA9 (TX)
PB7 (RX)		115200 8N1 塔克 XTARK SBTCOM1 蓝牙模块（4-pin 口）
USART6PG14 (TX)
PG9 (RX)		115200 8N1 K210 视觉 + 调试打印，共用同一条线
USART6 一线两用 —— 整套系统最容易踩的坑

debug_print() 和 k210_follow 都往 PG14 上写。 也就是说：K210 会收到底盘所有调试文字（启动信息、蓝牙帧统计、模式切换提示）。

K210 那边的解析必须能跳过这些垃圾行——按前缀 K210, / RM, 识别， 不是一个合法的行就整个丢掉。如果 K210 的接收逻辑是「收到什么就按固定格式切」， 一连调试打印就会解析失败甚至死机。

反过来，PG9（K210 发 → C 板收）是干净的，调试打印不会干扰。

K210 帧格式（底盘接收）

K210,seq,state,id,err_deg,dist_m*hh\n
字段含义
seq帧序号，底盘用它估丢帧率
stateL=锁定人 · S=画面没人 · X=视觉不可用
id跟踪目标 ID
err_deg人相对画面中心的水平偏角，正 = 人在右侧
dist_m距离（米），-1 = 未知。当前固件不用这个值
*hhXOR 校验

约 8 Hz 发送。底盘有 500 ms 看门狗，超时判定 K210 掉线 → 转向指令归零、原地停住。

底盘回传给 K210

RM,<mode>,<state>,<err_deg>,<w>\n   // 200 ms 一次

蓝牙帧格式（三种遥控源）

帧号来源结构
0x20手机 APPAA 55 0C 20 TY LX LY RX RY 键1 键2 SUM
0x90微信小程序AA 55 09 90 01 摇X 摇Y 键1 SUM
0xA0蓝牙手柄AA 55 0F A0 01 LX LY RX RY 键1 键2 键3 右扳机 左扳机 SUM
按键解析有两套定义，别混用

用蓝牙手柄（0xA0）时：

  • key1 是方向枚举，不是位掩码：1=上 3=右 5=下 7=左。 拿它当位掩码判断会永远判错。
  • key2 才是位掩码：bit0=A、bit6=LB、bit7=RB。

3.4 步进（俯仰轴）

信号引脚配置接驱动器
STEPPE9TIM1_CH1 · PWMTB6600 的 PUL+（PUL- 接 GND）
DIRPE11推挽输出TB6600 的 DIR+（DIR- 接 GND）
限位PE13输入 · 上拉限位开关一端接 PE13，另一端接 GND

限位开关怎么接、为什么低有效

PE13 内部上拉，开关常开、对 GND：没压住时读到高电平，压住时被拉到 GND 读到 0。 所以 STEP_LIMIT_ACTIVE_LEVEL = 0。

开关装在行程下端（零位），对应 STEP_LIMIT_AT_UP = 0。行为：

  • 压住 → 立刻停，并锁死「继续下降」这个方向
  • 反向（上升）永远放行，不会被限位卡住
  • 离开限位并持续 200 ms 后解锁
  • 压住时 stepper_get_pos() 清零 —— 这就是机械零位的定义方式
改驱动器细分拨码必须同步改代码

TB6600 现在是 8 细分，所以 STEP_STEPS_PER_REV = 200 × 8 = 1600。

如果为了降噪把拨码改成 16 细分，必须同时把代码改成 3200；改 32 细分改 6400。 不改的后果：实际转速是你设定值的几分之一，位置也全错，而且看起来像「电机没力」， 很容易误判成硬件故障。

3.5 无刷（DShot300）

通道引脚定时器说明
CH1PC6TIM8_CH1 三路共用 DMA2_Stream1 / Channel 7，TIM8 每个 update 事件搬 4 个字到 CCR1~CCR4（CH4 未用）。 缓冲布局 [槽][CH1,CH2,CH3,CH4]，共 50 槽 × 4 = 200 字。
CH2PI6TIM8_CH2
CH3PI7TIM8_CH3

DShot 帧是什么

// 16 bit 一帧，300 kbps
[ 11 bit 值 ][ 1 bit 遥测请求 ][ 4 bit CRC ]

值 = 0         → 停车
值 = 1~47      → 特殊命令（改方向、保存设置、蜂鸣…）
值 = 48~2047   → 油门，全部是正转，没有反向区间
想改电机转向，用 BLHeliSuite，不要改代码

标准 DShot 没有「反向油门」。要反转只有两条路：改电调内部相序，或者开 3D 模式。

最省事的是：USB-TTL 接上电调 → BLHeliSuite 里 Motor Direction 改 Reversed → Write Setup。 一次写入永久生效，比在固件里发命令字可靠得多（代码里的那套已经回退了）。

操作方式

按键作用
A 键（key2 bit0）按住才出力，松开立即停。速度档位保留
RB（key2 bit7）加速，每 50 ms 加 2.5%
LB（key2 bit6）减速，每 50 ms 减 2.5%

上电后先保持零油门 2 秒（DSHOT_ARM_MS = 2000），等 BLHeli_S 完成解锁。 这期间必须持续发合法帧，否则电调不认。

调无刷相关任何东西之前，先拆桨

包括：改 ESC_* 参数、连 BLHeliSuite 读参数、换电调、动信号线。

04上电会发生什么

知道这个顺序，出问题时能判断「卡在哪一步」。

1 · GPIO / CAN / 串口 / 定时器初始化
→
2 · CAN 滤波器
→
3 · 蓝牙 + 调试口
→
4 · LED + 步进
→
5 · DShot 起 DMA
→
6 · 等 2 秒解锁电调
→
7 · K210 串口
→
8 · 主循环
// main.c 里的实际顺序（简化）
MX_GPIO_Init();
MX_CAN1_Init();  MX_CAN2_Init();
MX_USART1_UART_Init();  MX_USART6_UART_Init();
MX_IWDG_Init();              // 看门狗，之后必须持续喂狗
MX_TIM1_Init();  MX_TIM8_Init();

can_filter_init();
bt_rc_init();                // 蓝牙，PA9/PB7
debug_port_init();           // 调试，PG14/PG9
led_ind_init();
stepper_init();              // DIR + 限位 + PWM 通道启动
DShot_Init();                // 环形 DMA，上电即持续发零油门帧

// 等电调解锁：1~3 秒，期间持续发帧并喂狗
while (HAL_GetTick() < arm_until) { HAL_IWDG_Refresh(&hiwdg); HAL_Delay(10); }

k210_follow_init();          // K210，USART6
while (1) { /* 10 ms 一拍的实时循环 */ }

主循环每拍做的事

  1. 读遥控/K210 数据，判断模式
  2. 全向轮逆解 → 四轮目标转速
  3. 四轮 PID → CAN 电流指令（发 0x200 帧）
  4. 步进方向 + 限位判断（10 ms 节拍）
  5. 无刷油门斜坡 + DShot 输出
  6. LED 指示 + 刷新 SWD 监控块 + 喂狗
看门狗是开着的

主循环任何一处阻塞超过 IWDG 超时时间，芯片会自动复位。 表现是「跑一会儿突然重启」「电机偶尔抽一下然后重新初始化」。 如果加了阻塞代码（比如 HAL_Delay 循环等待），记得在里面喂狗。

07故障排查

按现象查。顺序是刻意排的：先查线，再查配置，最后才怀疑代码。

这条经验值钱

「昨天能跑今天不能」——先想「今天动过什么线」，不要先想「代码哪错了」。 2026-11-03 那次步进完全不转，查了半天代码，最后是限位线断了（限位一直被判定压住，程序正确地禁止了下降）。

车不动 / 某个轮子不动

现象先查
四轮全不动CAN1 的 H/L 有没有接反、120Ω 终端电阻在不在、遥控是不是 RC 模式且在线
某一个轮不动那个电机的驱动器拨码是不是 1/2/3/4 对应位置；CAN 线是否串到位
能转但方向不对WHEEL_DIR_xx 宏；先确认不是电机装反
转起来发抖/异响PID 参数、CAN 反馈是否正常（看 _swd_mon_v2.py 的 rpm 字段）

步进不转 / 只往一个方向走

现象先查
完全不转限位线（PE13 断线 = 一直读高？不对，是读不到低。重点查开关是否被压住、线是否断）； TB6600 的 ENA 是否使能；驱动器供电
只能升不能降限位被判定压住 → 正常保护。检查开关是否卡住、STEP_LIMIT_AT_UP 是否写反
实际速度比设定慢很多细分拨码和 STEP_STEPS_PER_REV 不匹配
啸叫正常现象，随步频变化。降噪可以试 16/32 细分（记得同步改代码）

无刷异常

现象先查
上电不响、不转电调有没有动力电；DShot 信号线是否接在正确引脚
某一路不定时抖 / 停历史上这个是 DMA 指针错位（已修，214059b）。如果复发，查 dshot_apply() 是否三个寄存器一起复位
听到重新初始化音（哔几声）该路信号中断被判丢失 → 检查那一根线、焊点
转向反了BLHeliSuite 改 Motor Direction，不要改代码

K210 跟随不工作

现象先查
红灯 5 Hz 快闪K210 没上电 / 没跑程序 / TX 线没接在 PG9 上
红灯 1 Hz 慢闪通信正常，但 K210 报 S 或 X —— 画面里没人，或视觉算法没进入跟踪
锁定了但转向反K210_FOLLOW_DIR 改 -1
原地左右抖K210_DEADBAND_DEG 加大，或 K210_FOLLOW_KP 减小
K210 收到一堆乱码正常 —— 那是底盘的调试打印。K210 那边要能跳过非 K210, / RM, 开头的行

蓝牙遥控没反应

现象先查
绿灯慢闪链路离线：模块没上电、手机/手柄没连上、TX/RX 接反
红灯快闪收到数据但校验失败：波特率不是 115200，或接了别的设备
能收到但按键无效key1/key2 用错：key1 是方向枚举不是位掩码

程序跑一会儿自己重启

看门狗超时。找主循环里的阻塞点——最长见的是在循环里加了 HAL_Delay 或忙等， 又忘了喂狗。

08维护守则

安全第一
  • 调无刷一律拆桨。没有例外。
  • 上车通电前手扶稳。尤其是刚改完方向/增益，第一次上电可能猛冲。
  • 不要带电插拔电机线。CAN 和电调动力线都一样，会打火。

改代码的规矩

CubeMX 重新生成代码 —— 有前提
  • MDK-ARM/ctrl_2005.uvoptx 必须在且非空。缺了会报找不着文件； 0 字节会直接崩，而且日志只说「Problem in the update / KO」，完全看不出原因。
  • .mxproject 已经入库，不要忽略它。
  • USER CODE 3 那几个块必须包住 while(1) 的收尾 }， 否则 main() 会少一个括号，整个文件语法崩。
  • 不要在 USER CODE 2 里手动调 MX_TIM1_Init / MX_TIM8_Init —— 生成代码已经调了，重复调等于重复初始化 PWM。
  • 自己写的中断逻辑要塞进生成函数的 USER CODE BEGIN xxx_IRQn 0 槽位， 不能定义同名中断函数。
git status 里那 100 多个 Drivers 改动是假的

生成代码会按 ioc 声明的固件包覆盖 Drivers/， 导致 git status 显示一堆 M。用 git diff --name-only 看， 真正有内容差异的通常是 0 个 —— 纯粹是 LF/CRLF 行尾噪音，不要提交。

提交与留痕

  • 一轮改动 = 一次提交。提交信息写清：改了什么 / 为什么改 / 验证到哪一步 / 遗留什么。
  • 「验证到哪一步」必须诚实。没上机就写没上机，不要写「已修复」。
  • 改完在当天的日志里记一笔，让接手的人知道前因后果。

接手第一天该做的事

  1. 把本文第 3 节的接线表对着实物核一遍，特别是 CAN 拨码和步进限位
  2. 编译一次，确认 0 Error 0 Warning
  3. 不接电机，只上电看 LED 是否正常（RC 模式绿灯常亮）
  4. 跑一遍四个自检脚本
  5. 拆桨，试无刷；架空，试四轮转向；最后才落地
